## 一、架构问题 (Architecture)

### 问题 1.1: 目录结构不符合 Monorepo 规范
- **严重程度**: 🔴 高
- **当前状态**: 项目采用扁平结构，未使用 Monorepo 架构
- **规范要求**: 
  ```
  apps/web/     - 前端应用
  apps/server/  - 后端应用  
  packages/     - 共享库
  ```
- **影响**: 代码复用性差，模块化程度低
- **建议**: 保持当前结构（渐进式改进）或重构为 Monorepo

---

### 问题 1.2: 后端未遵循三层架构
- **严重程度**: 🟡 中
- **当前状态**: 所有业务逻辑直接写在 routes/*.js 中
- **规范要求**: Controller → Service → Repository 分层
- **影响**: 代码耦合度高，难以维护
- **建议**: 短期保持现状，长期重构

---

## 二、API 响应格式问题 (API Response)

### 问题 2.1: 响应格式不统一 ❌ 需立即修复
- **严重程度**: 🔴 高
- **当前状态**: 
  ```javascript
  // 情况1: 列表数据
  { success: true, data: { list: [...], total: n } }
  
  // 情况2: 单独对象
  { success: true, data: {...} }
  
  // 情况3: 仅消息
  { success: true, message: "..." }
  
  // 情况4: 纯数据
  { success: true, data: [...] }  // students.js
  ```
- **规范要求**:
  ```json
  {
    "code": 200,
    "message": "success",
    "data": {...},
    "traceId": "..."
  }
  ```
- **修复**: 需要重构所有后端路由，统一响应格式
