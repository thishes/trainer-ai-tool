### 登录 400 错误修复
- **根因**: schemas.js 中 login/register 的 captchaId/captchaCode 设为 `Joi.string().required()`，而 `required()` 不允许空字符串，导致前端 captchaId 初始值为空时被 Joi 拦截返回 400
- **修复**: captchaId/captchaCode 改为 `Joi.string().allow('')`，username 改为 `min(1)`，password 改为 `min(1)`，业务验证由路由代码 `if (!captchaId || !captchaCode)` 处理
- **验证**: 服务器重启后，所有登录场景返回正确的业务错误而非 Joi 验证错误
- 前端重新构建成功（main-6dec816d.js + Dashboard-f77cdb39.js）

### MySQL 连接问题排查与修复
- **现象**: 服务器启动时 MySQL 连接池 ETIMEDOUT，但独立 mysql2 连接正常
- **根因**: 远程 MySQL (kb.thishe.com:33060) 连接延迟高(~2s)，连接池首次建连可能超时
- **修复**:
  - `db-mysql.js` connectTimeout 从 5s → 15s
  - 移除 `idleTimeout`/`maxIdle` 参数（可能不被当前 mysql2 版本正确处理）
  - `healthCheck()`: 连接池失败时销毁旧池 + 用独立连接验证 MySQL 可达
  - `reconnect()`: 先用独立连接测试 MySQL 可达，再重建连接池
  - `ensureIndexes()`: `CREATE INDEX IF NOT EXISTS` 语法不被 MySQL 8.0.45 支持，改用 information_schema 查询 + ALTER TABLE ADD INDEX 批量创建；索引列名修正(papers.owner_id→user_id, exam_records.student_id→user_id)
  - `init()`: ensureIndexes 失败不影响 isConnected 状态
  - `index.js`: 合并重复的 dbMysql.init() 和 db.initMySQL() 调用，只保留一次；添加 MySQL 未连接时自动重连逻辑（30s 检测间隔）
  - `db.js`: 新增 `setMySQLReady()` 方法
- **索引列名修正**: papers.owner_id → papers.user_id, exam_records.student_id → exam_records.user_id
- **初始化性能**: ensureIndexes 从 36s 缩短到 ~5s（批量创建 + 去除 queryWithRetry 重试）
- **启动流程**: 服务器先启动（HTTP 可用），MySQL 后台异步连接（30s 内自动重连）
